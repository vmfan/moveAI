# Implementation Roadmap — Intake → Quote → Booking Workflow

Tracks the sequential builds that wrap the existing single-image volume-estimation pipeline (`moveai_prototype/`) in the full customer workflow specified in `DESIGN.md`. Each build gets its own plan-mode session: read this file, confirm scope for that build only, execute, verify, update status here, stop. Don't start a build whose dependencies aren't marked complete. Each build's session ends with a commit containing both the code changes and this file's updated status/notes — the status table is only trustworthy if it stays synchronized with git history, so a build isn't real until it's committed.

## How to resume

1. Read `DESIGN.md` first — the product vision and the contracts (especially §5a inter-stage schemas and §5c volume→quote contract) that every build must satisfy.
2. Read this file's status table and build notes below.
3. **Cross-check the status table against `git log`/`git status` before trusting it.** If a build is marked complete but its files aren't in git history, the table is stale — treat git as the source of truth over the table.
4. Pick the next "Not started" build whose dependencies are complete, and scope that build only.

## Known environment constraints

Fallback verification method: exercise the real code path with synthetic/hand-built data (see Build 1's note below) rather than a full pipeline run, and flag in the build notes when this substitution was used.

## Build notes

**Build 1 — axis-semantics fix.** `ObjectMeasurement.dimensions_m` (`geometry.py`) discarded which fitted-box extent was width/height/depth. Fixed by classifying each local box axis via the box's rotation `box.R` against camera-frame axes (depth ≈ camera-forward, height ≈ up, remainder is width), replacing `dimensions_m: np.ndarray` with named `width_m`/`height_m`/`depth_m` fields and adding `used_axis_aligned_fallback: bool`. Call sites updated: `app.py` (two unpacking sites + UI column labels), `smoke_test.py` (JSON export field names), and `generate_presentation_assets.py` (missed by the original plan — found by grep, consumed `smoke_test.py`'s old `obb_edges_m` JSON key in two places).

Verification note: the full pipeline couldn't run end-to-end in this environment (Grounding DINO isn't cached locally and `local_files_only=True` blocks the download — pre-existing, unrelated to this change). Verified instead with a synthetic-scene unit check that exercises the real `measure_detection`/`_named_dimensions` code path via Open3D: a frontal-shell object correctly resolves `depth_m` as the smallest axis, plus direct checks of `_named_dimensions` against identity and rotated rotation matrices. All four edited files pass `py_compile`.

**Build 2 — SQLite persistence layer.** New `db.py`: tables for `job`, `intake`, `inventory_item` (unifies measured/prior_assisted/declared items and boxed-goods lines via `measurement_basis` + `is_boxed_goods`), `pricing_config` (company-configurable, seeded with a default row, currency HKD), `quote`/`quote_line` (versioned — new quotes are inserted, never mutated, prior version flagged superseded), `booking`. See `DESIGN.md` §5a/§5c for the contracts this schema must satisfy. Stdlib `sqlite3` only, no ORM; module stays free of Streamlit/pipeline imports so it can run without the model stack. `config.py` gained `DB_PATH` (overridable via `MOVEAI_DB_PATH`).

Contracts from §5a/§5c are enforced as schema `CHECK` constraints rather than left as convention: boxed-goods lines can't carry dimensions, `measured` items can't carry `prior_assisted_axes`, `quote_line.surcharge_eligible` is forced to agree with `measurement_basis` (the surcharge contract), and a partial unique index caps `pricing_config` at one active row. `customer_confirmed` is a column separate from `review_state` so confirming an item structurally cannot clear a staff escalation. Quotes are versioned by inserting a new row and flagging the previous one superseded within `create_quote()`, never mutating in place.

Verification: `db_smoke_test.py` (committed) exercises the full job → intake → inventory → quote-v1 → quote-v2 → booking lifecycle against a throwaway SQLite file, including an intake re-submit (upsert, not duplicate), all four inventory line types, the customer-confirm/staff-escalate independence rule, and four negative cases each asserting `sqlite3.IntegrityError` on a `CHECK`/unique-index violation. 24/24 checks pass; `db.py`, `db_smoke_test.py`, and `config.py` pass `py_compile`. No substitution needed — this module needs no model weights, so it was verified for real rather than synthetically.

**Build 3 — pricing engine + boxed-goods estimator.** Pure functions, no I/O, mirroring `pipeline.py`/`geometry.py` in staying Streamlit-agnostic. `upper_bound_volume_m3()` is the single place the margin is applied — `pricing_smoke_test.py` proves this by asserting `Σ line.volume_m3 == upper_bound_volume_m3(Σ line_raw, margin)` to float tolerance, which only holds if margin was applied exactly once. `access_multiplier()` combines origin/destination legs from intake floor/lift/parking data **additively** (each leg's surcharge is summed, not compounded) — see the market research below for why. Boxed-goods gets its own labour weight (`boxed_goods_labour_multiplier`) applied only to `is_boxed_goods` lines. `recommend_truck()` is a separate function from pricing per `DESIGN.md` §5c, selecting the smallest truck whose *usable* capacity (72% of nominal, honestly stated as a fitting-geometry factor, not a second margin) clears both volume and the largest item dimension; escalates `oversize_item` when nothing fits and computes multi-trip counts when volume exceeds the whole fleet.

`priors.py` is the single class-priors artifact `DESIGN.md` §4 calls for, serving one of its three jobs this milestone: `boxes_for_storage_label()` is populated with box-count ratios, consumed by `boxed_goods.py`'s `estimate_boxed_goods()`. The other two jobs — `flag_implausible_dimension()` (plausibility bounds) and `expected_depth_m()` (occluded-axis substitution) — are explicit stubs returning no signal, per the roadmap's original scope. `DimensionFlag` carries a `has_prior: bool` alongside `flagged` so a caller (Build 5) can tell "no prior exists" apart from "checked and plausible" rather than reading a bare `False` as an endorsement — this wasn't in the original build note but followed directly from keeping the stub honest.

Also added beyond the original build note, both scoped in during planning once market research was available: **`declared_excess_surcharge()`** in `pricing.py` implements `DESIGN.md` §5c's day-of surcharge contract (fires only on `declared`-quantity error, never on `measured`/`prior_assisted` volume) as a tiered function against total price; no new `pricing_config` schema needed. **Recalibration of `db.py`'s seeded `pricing_config`**: `floor_multiplier_per_level` changed `0.08 → 0.15`; `base_callout_fee`/`price_per_m3` left unchanged after cross-checking they land the Consumer Council's worked case in-band.

*Hong Kong market research (via web search, informing the above):* the [HK Consumer Council's 2024 survey of 20 removal companies](https://www.consumer.org.hk/tc/article/573-home-removal-service/573-home-removal-service-price-comparison) found stair/no-lift charges (樓梯費) run **15–20% of the total per floor** (a floor = 15–20 steps), up to 30% at the priciest outlier — this set both the recalibrated `floor_multiplier_per_level` and the additive-not-multiplicative leg-combination rule, matching §5c's "never stack" principle. The same survey documents the day-of excess convention: **+20% of total if actual goods exceed the estimate by >20%, +30–50% if by >50%**, which became `DECLARED_EXCESS_TIERS`. No surveyed HK company itemises a parking-distance surcharge (that's a US "long carry beyond 75–100 ft" convention), so `pricing.FREE_CARRY_DISTANCE_M = 20.0` keeps short walks from inflating the quote via the otherwise-unused intake field. Fleet specs (Lalamove/GoGoX public pricing pages, cross-checked against a general HK truck reference table) set `HK_FLEET`: van ~5.7 m³, 14ft/3-tonne ~11 m³, 16ft/5.5-tonne ~18 m³, 9–10-tonne ~33 m³. The Consumer Council's worked standard case (5-person family, North Point→Mei Foo, 40 furniture items + 35 cartons, quoted HK$3,818–12,162, 2026 mid-size average HK$8,000–12,000) is used twice as a calibration anchor: `pricing_smoke_test.py` reconstructs it and asserts the resulting price lands in that band (got ~HK$10,600 for a 3rd-floor no-lift origin), and `boxed_goods.estimate_boxed_goods()` reconstructs its storage/room composition and asserts 36 boxes against the surveyed 35.

Verification: `pricing_smoke_test.py` (committed, 40/40 checks pass) — no model weights needed, so this is real verification like Build 2, not Build 1's synthetic substitution. Covers the no-stacked-margin invariant, access-multiplier arithmetic against the worked HK cases (including the additive-vs-multiplicative distinction and the parking free-threshold), boxed-goods labour isolation, escalated/unmeasured items surfacing on the `Quote` rather than vanishing (§5b), truck selection at capacity boundaries and oversize/multi-trip escalation, all three day-of-surcharge tiers, both boxed-goods calibration cases, the `priors.py` stub's `has_prior` signal, and an integration check piping `build_quote()` output through `db.create_quote()` against a throwaway SQLite file to prove the `CHECK` constraints (not just the dict shape) are satisfied. `db_smoke_test.py` re-run clean (24/24) after the seed recalibration. All five touched/added files pass `py_compile`.

**Build 4 — Intake page + job spine.** `pages/1_Intake.py` (`st.form` for contact/addresses/floor/lift/parking/room-count/preferred-date), validated by new `inventory_sync.intake_validation_errors()` before it reaches `db.save_intake()`. `job_id` lives in `st.session_state` and is mirrored to `st.query_params` via new `job_context.py` (also home to the cached `db.connect()`/`db.initialize()` resource and the sidebar job-status widget shared by every page). `app.py` gets soft `job_id` integration: a **Room** sidebar field, and — inside the existing `analyze` block, so a Streamlit rerun can't double-insert — a call to new `inventory_sync.persist_capture()` that writes each measured object plus any failed detections as `inventory_item` rows. Standalone usage without an active job is unchanged.

Two scope calls made explicit during planning, both because the alternative would have permanently lost data no later build could recover: (1) `geometry.py` gained the border-touching signal (`ObjectMeasurement.mask_touches_border`, via new `_mask_touches_border()`) and a `MeasurementFailure` dataclass replacing the bare strings `measure_all()` used to return for failed detections — masks aren't persisted to the DB, so a signal not captured at measurement time is gone forever, and `app.py`/`smoke_test.py` needed the failure's structured fields (not just a display string) to write an escalation row. Build 5 still owns the §5b review-*state* policy; this only makes the raw signals it needs available on the persisted row. (2) captured items are tagged with a customer-adjustable **Room** field rather than left `NULL`, since DESIGN.md §5a requires room assignment and Build 5 groups by room.

A failed measurement is persisted as `measurement_basis='measured'`, `review_state='staff_escalate'`, dimensions NULL, `measurement_error` set to the failure message — §5b's "a failed measurement is never silently dropped" applied at the point the data first exists, not deferred to Build 5. Re-running the same photo (`source_image_name` match) replaces its prior rows rather than duplicating them.

Verification: `job_flow_smoke_test.py` (new, committed, 34/34 checks pass) — no model weights needed, real verification like Builds 2–3. Covers intake validation (required fields, malformed email, negative floor/parking, `room_count < 1`), the border-touching helper against synthetic masks, a saved intake feeding `pricing.AccessFactors.from_intake()`/`access_multiplier()` with no `KeyError` (proving Build 4's form satisfies Build 3's contract), `persist_capture()`'s full round-trip (named dimensions, room label, provenance JSON, border signal, escalation row shape, re-capture idempotency, a second distinct photo adding alongside), and an integration check piping persisted rows through `pricing.build_quote()` to confirm the escalated item is reported rather than dropped. All seven touched/added files pass `py_compile`.

**Build 5 — Inventory Review page.** Implements the `DESIGN.md` §5b interrupt rule. New `review_policy.py` (pure, no db/Streamlit imports, mirroring `pricing.py`/`priors.py`) turns Build 4's recorded signals into the three named states, resolving a genuine tension in §5b: its interrupt-rule sentence names only shell ratio/border truncation/implausible dimension as customer-confirm triggers ("the customer cannot assess whether a measurement is geometrically sound"), while this roadmap's original Build 5 line separately listed low point count and axis-aligned fallback as signals to act on. Resolved by routing the geometric-soundness signals — ones a customer has no basis to judge — to `staff_escalate` instead of a customer prompt, and reserving `customer_confirm` for signals a plain-language question can resolve. `DESIGN.md` §5b gained a paragraph recording this so the two sections don't read as contradictory to a future reader. Full mapping: border truncation and detection confidence < 0.35 → `customer_confirm`; axis-aligned fallback and point count < 200 → `staff_escalate`; a measurement failure (Build 4, unchanged) → `staff_escalate`; shell ratio/implausible dimension → `customer_confirm`, wired but never fires today since `priors.py`'s two stubs still report `has_prior=False`. Both numeric thresholds are explicit uncalibrated placeholders per `DESIGN.md`'s Calibration section. Precedence is `staff_escalate` > `customer_confirm` > `auto_accept` (an item flagged both ways escalates). `persist_capture()` (`inventory_sync.py`) now calls `classify()` and writes the resulting state instead of relying on the schema's `auto_accept` default.

`inventory_sync.py` also gained the mutation half of the review loop: `seed_boxed_goods()` (idempotent — one boxed-goods line per job, calls the existing `boxed_goods.estimate_boxed_goods()` and seeds it as `customer_confirm` rather than `auto_accept`, since §5c's surcharge contract only stands up if the customer actually saw and owned the count before it entered the quote), `set_boxed_goods_count()`, `confirm_item()`, `apply_customer_correction()`, and `add_declared_item()`.

Two scope calls made explicit during planning, both confirmed with the user rather than assumed: (1) a customer **correction** (not mere confirmation) flips `measurement_basis` from `measured` to `declared` — the number moving forward is what the customer typed, so §5c's day-of surcharge, not the estimation-error margin, covers it if wrong. This reads against §5a's literal "`declared` — no underlying detection at all", so the original measured values are preserved under `provenance_json.customer_override` rather than discarded (§5a: provenance is mandatory), and the page states the surcharge consequence before the customer edits. (2) The page supports **manual add** of a `declared` item the pipeline never saw at all (§5a names this explicitly) — auto-accepted and pre-confirmed, since the customer just typed it in themselves. In both new-item paths and in every state transition, confirming or correcting a `customer_confirm` item promotes it to `auto_accept`, but nothing ever clears a `staff_escalate` state beyond setting `customer_confirmed` — §5b's independence rule, already enforced structurally by `db.py`'s separate columns (Build 2), is now also honoured by every write path that reaches them.

`pages/2_Inventory_Review.py` follows `pages/1_Intake.py`'s established shape (job-spine access via `job_context`, `st.page_link` wrapped in `try/except` for the same `AppTest` multipage-registry limitation Build 4 found). Sections: needs-your-confirmation (confirm / correct via popover / remove), boxed goods (adjustable count with the seed breakdown in an expander so the number isn't a black box), your inventory (grouped by room), being-reviewed-by-our-team (read-only), add-an-item-we-missed, and a footer count summary.

Verification: `inventory_review_smoke_test.py` (new, committed, 43/43 checks pass) — no model weights needed, real verification like Builds 2–4. Covers every row of the signal→state table plus precedence, the priors stubs correctly reporting no signal (`has_prior=False`, never scored as a pass), `persist_capture()` writing the computed state end-to-end, boxed-goods seed idempotency and the customer-adjustment round-trip, the correction basis-flip with recomputed volume and preserved provenance, the non-negotiable confirm-does-not-clear-escalation rule, manual add landing as `declared`/pre-confirmed, and an integration check piping a reviewed inventory through `pricing.build_quote()` + `db.create_quote()` confirming the corrected item is surcharge-eligible and the escalated item is still reported rather than dropped. Also drives the real Inventory Review page headlessly via `AppTest` (no active job, a seeded job, and a Confirm click that actually writes the row). `db_smoke_test.py` (24/24), `pricing_smoke_test.py` (40/40), and `job_flow_smoke_test.py` (34/34) re-run clean — the last one was the regression risk, since `persist_capture()`'s behaviour changed, and it passed unmodified because it only asserts row *shape*, not the (previously-default) `review_state` value. All new/touched files pass `py_compile`. Manual `streamlit run app.py` confirmed HTTP 200 on `/`, `/Intake`, and the new `/Inventory_Review`.

**Build 6 — Quote page.** Loads confirmed inventory + intake access factors + active `pricing_config`, calls `pricing.build_quote()`, displays line items labelled by `measurement_basis`, shows recommended truck, persists as a new quote version on each generation.

**Build 7 — Booking Confirmation + Company Console.** Booking Confirmation creates a `pending_staff_review` booking row. Company Console is a separate, unauthenticated staff view (explicitly flagged as prototype-only, not production-ready) listing bookings with status transitions.

## Explicit scope exclusions (apply across all builds)

No auth, no payments, no real notifications, no video/multi-frame capture, no populated class-priors table, no multi-room logic beyond a `room_count` passthrough parameter, no inventory versioning (only quotes are versioned).
